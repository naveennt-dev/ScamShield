# Final Security Audit — 2026-10-07

Scope: the repository after the production upgrade. Method: manual review of every entry point
against `threat-model.md`, targeted greps, adversarial tests, dependency audit. This is an internal
engineering review, not an independent penetration test.

## Verified controls

- **AuthZ**: every history/report/settings/stats query includes `userId` from the session; foreign
  IDs → 404; strict schemas reject `userId` in bodies (integration tests).
- **CSRF**: cross-site `Origin` rejected on writes; JSON content type required; better-auth origin
  checks; session cookie `HttpOnly; Secure; SameSite=Lax` (observed on a live sign-up response).
- **CSP**: nonce + `strict-dynamic`; E2E main flow records zero CSP console violations.
- **Secrets**: no `NEXT_PUBLIC_` variables; no secrets in repository files (grep); `.env*` ignored
  except `.env.example`; health endpoint returns no connection strings (integration test).
- **Errors**: envelope never includes stacks (integration test checks error bodies).
- **Uploads**: content sniffing, extension match, dimension limits, streaming byte cap (unit +
  integration tests); images not persisted.
- **Open redirect**: `/auth?next=` accepts only same-site relative paths.
- **Machine endpoints**: metrics/cron disabled unless tokens set; constant-time comparison.

## Accepted / residual risks

| Risk | Rationale / follow-up |
|---|---|
| `style-src 'unsafe-inline'` | Required by Next.js/framer-motion inline styles; scripts remain nonce-locked |
| Build/dev-time advisories: PostCSS bundled in Next (8.4.31), `deepmerge-ts` in Prisma CLI, `braces` in `eslint-config-next` | Not reachable from user input at runtime. Clearing them requires Next 16 / Prisma 7 / newer ESLint config — schedule as a separate upgrade |
| Anonymous IP-based limits evadable with many IPs | Disable anonymous analysis or add a WAF/bot protection if abused |
| Crowd-report poisoning via many accounts | Reports can only raise scores, need ≥2 reporters, capped weight; build a reviewer workflow |
| Free OpenRouter models may log prompts | User opt-out exists; document in privacy policy or use paid models with retention guarantees |
| Masking is heuristic | Names/addresses are not masked in previews; users can disable previews |
| OCR language data fetched from CDN | Self-host via `OCR_TESSERACT_LANG_PATH` |
| No MFA / account lockout beyond better-auth defaults | Out of scope for this upgrade |

## Not performed

External penetration test, load testing, dependency SBOM/signing, infrastructure review
(network egress rules, DB access policies), formal privacy/legal review.
